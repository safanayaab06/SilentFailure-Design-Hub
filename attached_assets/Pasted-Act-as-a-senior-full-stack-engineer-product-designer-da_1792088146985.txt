## 7. TRANSPARENT RISK ENGINE

Implement a dedicated, testable Python function for assessing telemetry.

Use configurable thresholds for:
- Response latency
- Error rate
- Memory utilization
- Repeated lag or freeze events
- Deterioration across consecutive readings

For each reading:
1. Validate input values.
2. Check each threshold.
3. Record each triggered rule.
4. Calculate the score from the triggered rules.
5. Map the score to a status.
6. Return the score, status, reasons, and suggested actions.

Use an understandable score system, for example:
- Zero or one triggered condition: `NORMAL`
- Two or three triggered conditions: `WARNING`
- Four or more triggered conditions: `HIGH CONCERN`

Tune the sample scenarios so each produces the expected status. Avoid arbitrary score inflation and document how the rules work.

Make thresholds editable in Settings. The assessment must update when thresholds change.

Add tests or internal validation for:
- Healthy readings
- Degraded readings
- High-concern readings
- Missing or invalid values
- Threshold changes
- Repeated readings

Do not call this a trained AI model. Describe it as an explainable, rule-based prototype that could later be compared against validated machine-learning methods.
